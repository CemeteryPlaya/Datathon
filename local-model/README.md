# Модель cqa-local-v1

Здесь лежит нейросеть, которая оценивает диалоги. Мы написали её на PyTorch и обучили с нуля: никаких готовых
моделей, предобученных весов или внешних API она не использует. Как запустить проект целиком, написано в
[README в корне](../README.md), а все цифры по качеству — в [REPORT.md](REPORT.md).

Главная идея: модель один раз «читает» диалог и сразу отвечает на все вопросы чек-листа. Вопрос — это просто текст
критерия из редактора (название и описание), а на выходе модель даёт вероятность для каждого варианта ответа
(«да», «нет», «N/A» или ступень шкалы). Поэтому новый критерий можно добавить в интерфейсе, и модель его поймёт без
переписывания кода. Насколько хорошо поймёт, зависит от того, похож ли он на то, что она видела при обучении.

## Запуск сервиса модели

Если вы уже запустили `setup.cmd` из корня проекта, окружение готово, и сервис стартует сам через `start.cmd`.
Вручную (Windows, из корня проекта):
```
py -3 -m venv local-model\.venv
local-model\.venv\Scripts\python.exe -m pip install torch --index-url https://download.pytorch.org/whl/cpu
local-model\.venv\Scripts\python.exe -m pip install -r local-model\requirements.txt
local-model\.venv\Scripts\python.exe local-model\serve.py
```
Первые три команды нужны только один раз. Сервис запускается на http://127.0.0.1:8000 и доступен только с этого
компьютера. Проверка: открыть http://127.0.0.1:8000/health. Порт можно поменять через `LOCAL_MODEL_PORT` в `.env`,
тогда поменяйте и `LOCAL_MODEL_URL`, чтобы приложение знало, куда обращаться.

Веса уже лежат в `weights/cqa-local-v1.pt`, обучать ничего не нужно.

## Что модель показывает в интерфейсе

- В карточке диалога у каждого критерия есть полоска вероятностей, например «нет 82% · да 15%».
- Объяснение собирается по шаблону: ответ, вероятность и цитата реплики-доказательства. Для ответа «Нет» пишется,
  какой участок диалога проверялся, для N/A — какое условие сработало.
- Если уверенность ниже 75%, критерий помечается «Проверить».
- На экране «Апелляции» есть кнопка «Дообучить модель по решениям». Она берёт рассмотренные апелляции по одному
  критерию (нужно минимум 5 разных диалогов) и за несколько секунд подстраивает модель под этот критерий.
  Перезапускать сервис не нужно.

## Как устроена модель

Упрощённая схема:
```
диалог → реплики → текстовый энкодер + признаки реплик → 2 слоя трансформера → представление диалога
вопрос и варианты ответа → тот же текстовый энкодер
совпадения слов вопроса со словами в репликах оператора → подсказка, куда смотреть
вопрос «смотрит» на реплики (attention) → оценка каждого варианта → softmax → вероятности
```

Немного подробнее:
- **Токенизация без словаря.** Вместо готового токенизатора мы режем текст на кусочки по 3–5 символов и хешируем
  их. Так одинаково работает для русского, казахского и английского и не ломается на опечатках и ошибках
  распознавания речи в звонках.
- **Признаки реплик.** Кроме текста, модель знает роль (клиент, оператор, бот, система), позицию в диалоге, паузы и
  важные события: передача оператору, подтверждение личности, обрыв связи, удержание, закрытие чата. События
  считаются на стороне Node.js (`server/model/events.js`) и передаются в модель вместе с диалогом.
- **Доказательства.** Реплики, на которые модель больше всего «смотрела», становятся ссылками-доказательствами,
  а проверенный участок — это отрезок диалога, где сосредоточено основное внимание.
- **Обучение.** В основном на синтетических диалогах из нашего генератора (`datagen/`), плюс 20 реальных диалогов
  с ручной разметкой и их изменённые копии. Модель — это ансамбль из трёх сетей с разными seed, всего около
  9.9 млн параметров.
- **Честная проверка.** Диалоги из `data/gt-holdout` и их копии никак не участвуют в обучении, поэтому метрики
  на них показывают реальное качество. Это проверяется в коде при каждом запуске обучения.
- В коде модели нет привязки к конкретным критериям стартового чек-листа: модель получает только их текст.

## Обучение заново

Сначала нужно сгенерировать данные, потом обучить (из корня проекта):
```
npm run datagen
local-model\.venv\Scripts\python.exe local-model\baselines.py
local-model\.venv\Scripts\python.exe local-model\train.py
local-model\.venv\Scripts\python.exe local-model\predict.py
local-model\.venv\Scripts\python.exe local-model\evaluate.py --models majority,rules,cqa-local-v1 --detail gt-holdout
```
- `npm run datagen` — синтетические диалоги и разметка, около минуты.
- `baselines.py` — два простых способа для сравнения: «всегда самый частый ответ» и «правила на регулярках».
- `train.py` — обучение, около 40–50 минут на процессоре. Если есть видеокарта с CUDA, можно добавить
  `--device auto`. Результат сохраняется в `weights/cqa-local-v1.pt` (старые веса перезапишутся).
- `predict.py` и `evaluate.py` — считают предсказания и метрики на тестовых наборах.

## API сервиса

Это нужно, только если хотите обращаться к модели напрямую, а не через приложение.

`GET /health` — информация о модели: число параметров, дата обучения и т. д.

`POST /v1/decide` — оценить диалог:
```
{ "record": { "conversation_id", "channel", "language", "transcript": [...] },
  "events": [...], "offsets": [...],              // необязательно
  "questions": { "<ключ>": { "type": "noul" | "choice" | "score",
                             "criterion": { "name", "description", "type", "levels", "polarity", "na_allowed", "na_condition" },
                             "options": [ { "key": "yes", "text": "Да" }, ... ] } } }
```
Ответ:
```
{ "model": "cqa-local-v1", "duration_ms": 12, "operator_name": "Алина",
  "answers": { "<ключ>": { "choice": "yes", "probabilities": { "yes": 0.82, "no": 0.18 }, "confidence": 0.82,
                           "evidence": [9], "checked_range": [9, 14] } } }
```
Для шкалы в ответе есть ещё `score` — ожидаемое значение балла.

`POST /v1/finetune` — дообучение под один критерий:
`{ "question": { "criterion": {...} }, "examples": [ { "record", "events", "answer" } ] }`.
Нужно минимум 5 примеров. Основная сеть при этом не меняется, обучается только небольшая добавка под этот
критерий. Она сохраняется в `weights/adapters/` и сразу применяется к новым оценкам.

## Ограничения

- Модель маленькая и училась в основном на синтетике, поэтому на реальных диалогах ошибается заметно чаще, чем
  на синтетических. Хуже всего с «корректностью консультации» и «управлением диалогом».
- Критерии, которых не было в обучении, она часто уверенно оценивает как «нет», и пометка «Проверить» появляется
  не всегда. Помогает дообучение на 5–10 решениях по апелляциям.
- Ручная разметка, по которой мы считаем точность, черновая, а реальных тестовых диалогов всего 13, так что
  разброс у метрик большой.
- Казахские тексты в синтетике никто из носителей языка не вычитывал.
