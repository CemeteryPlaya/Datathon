# Ручная разметка DEV

Здесь лежат правильные ответы по стартовому чек-листу для части диалогов из DEV. По ним мы считаем, насколько
точно работает модель. Один файл на диалог: `<conversation_id>.json`.

Разметка разбита на три папки, чтобы не подгонять модель под одни и те же диалоги:
- `data/gt` — 20 диалогов, на них модель училась и на них мы разбирали ошибки;
- `data/gt-fresh` — 8 диалогов для валидации во время обучения;
- `data/gt-holdout` — 13 диалогов только для финальной проверки. В обучении они не участвуют.

Посчитать точность модели по любой из папок (сначала диалоги должны быть оценены):
```
npm run accuracy -- --gt data/gt-holdout
```

**Важно:** это черновая разметка, сделанная по правилам из PDF с чек-листом. Её стоит перепроверить вручную,
особенно казахские диалоги.

Поле `ambiguous` — критерии, где даже два человека могли бы ответить по-разному. Точность считается и с ними, и
без них.

Правила, которых мы придерживались при разметке:
- **c07 «Завершение»:** одного прощания мало, нужно прощание плюс итог разговора или предложение ещё помочь.
  «Отлично. Хорошего дня!» — это «Нет».
- **c07:** если оператор закрыл чат и не попрощался — «Нет»; если связь оборвалась сразу после ответа — N/A.
- **c02 «Выявление потребности»:** N/A, если информации хватало с самого начала и оператор сразу ответил по делу.
- **c03 «Идентификация»:** N/A, если оператор не раскрывал данные счёта и не делал действий, для которых нужна
  проверка личности.
