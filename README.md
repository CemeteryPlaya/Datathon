# CQA — оценка качества диалогов поддержки

Это наш проект для хакатона Freedom Broker. Система берёт диалог клиента с оператором поддержки и проверяет его
по чек-листу: поздоровался ли оператор, проверил ли личность клиента, правильно ли ответил, вежливо ли закончил
разговор, не было ли грубых ошибок.

Оценивает диалоги наша собственная нейросеть `cqa-local-v1`. Мы обучали её с нуля, без готовых моделей. Она работает
прямо на компьютере (на процессоре, видеокарта не нужна), без интернета и бесплатно.

Что умеет проект:
- оценивать диалоги на русском, казахском и английском (чаты и звонки);
- по каждому критерию показывать ответ, объяснение и ссылку на реплику, на основе которой модель так решила;
- считать итоговый балл и отдельно отмечать грубые ошибки;
- менять чек-лист прямо в интерфейсе: добавлять, удалять и редактировать критерии без правки кода;
- работать с апелляциями: оператор оспаривает оценку, проверяющий принимает решение, балл пересчитывается;
- дообучать модель на решениях проверяющих одной кнопкой;
- показывать сводку для руководителя, профили операторов и список грубых ошибок.

## Что нужно заранее

- **Windows 10/11** (скрипты запуска сделаны под Windows; про Linux/macOS — в конце раздела «Запуск»).
- **Node.js 20 или новее** — https://nodejs.org (берите версию LTS).
- **Python 3.10 или новее** — https://www.python.org/downloads/. При установке обязательно поставьте галочку
  «Add python.exe to PATH», иначе скрипты его не найдут.
- Интернет — только на время установки: скачается около 300 МБ, в основном это PyTorch.

Проверить, что всё установлено, можно в командной строке:
```
node -v
py -3 --version
```

## Установка (один раз)

1. Распакуйте архив с проектом в любую папку. Лучше, чтобы в пути не было пробелов, например `D:\Datathon`.
2. Дважды щёлкните по файлу **`setup.cmd`**.
3. Подождите 2–5 минут. Скрипт сам:
   - поставит пакеты для сервера (`npm install`);
   - создаст отдельное окружение Python для модели в папке `local-model\.venv`;
   - поставит туда PyTorch и остальные библиотеки;
   - создаст файл настроек `.env`.
4. Когда появится надпись `Done. To start the app run start.cmd`, установка закончена.

Сообщения в скриптах на английском специально: русские буквы в `.cmd`-файлах ломают командную строку Windows.

Если удобнее руками, то же самое делают эти команды (из папки проекта):
```
npm install
py -3 -m venv local-model\.venv
local-model\.venv\Scripts\python.exe -m pip install torch --index-url https://download.pytorch.org/whl/cpu
local-model\.venv\Scripts\python.exe -m pip install -r local-model\requirements.txt
copy .env.example .env
```

## Запуск

Проект состоит из двух частей, и обе должны работать одновременно:
1. **сервис модели** (Python) — сама нейросеть, работает на http://127.0.0.1:8000;
2. **приложение** (Node.js) — сервер и веб-интерфейс, работает на http://localhost:3000.

Проще всего дважды щёлкнуть по **`start.cmd`**. Он откроет два окна — «CQA model» и «CQA app» — и через несколько
секунд браузер с приложением. Модели нужно 5–10 секунд, чтобы загрузиться, так что если первая оценка выдала
ошибку, просто подождите и повторите.

Чтобы всё выключить, закройте оба окна.

Запуск вручную, в двух отдельных окнах командной строки (из папки проекта):
```
local-model\.venv\Scripts\python.exe local-model\serve.py
```
```
npm start
```
После этого откройте в браузере http://localhost:3000. Проверить, что модель работает, можно по адресу
http://127.0.0.1:8000/health — там должен быть ответ с `"model": "cqa-local-v1"`.

На Linux/macOS скрипты `.cmd` не работают, но ручной запуск тот же, только пути другие: окружение создаётся через
`python3 -m venv local-model/.venv`, а Python лежит в `local-model/.venv/bin/python`.

## Как пользоваться

В проекте уже лежат оценки всех 65 диалогов учебного набора DEV и 10 контрольных чатов FBroker, так что экраны
сразу не пустые. Справа вверху есть переключатель роли: **Оператор** или **Проверяющий**. Входа по паролю нет,
это просто переключатель для демонстрации.

Разделы в меню:
- **Сводка** — общая картина: средний балл, грубые ошибки, апелляции, самые проблемные критерии, разбивка по
  языкам, каналам и операторам.
- **Диалоги** — список всех диалогов. Отметьте нужные галочками и нажмите «Оценить выбранные» или «Оценить все».
  65 диалогов оцениваются примерно за 5–15 секунд.
- **Карточка диалога** (открывается кликом по диалогу) — слева переписка, справа оценка по каждому критерию.
- **Операторы** — статистика по каждому оператору и советы, что ему подтянуть.
- **Тревоги** — диалоги с грубыми ошибками.
- **Апелляции** — очередь апелляций и кнопка дообучения модели.
- **Чек-листы** — редактор критериев.

В карточке диалога у каждого критерия есть:
- ответ модели (Да / Нет / N/A / балл по шкале);
- полоска с вероятностями, например «да 96% · нет 4%»;
- объяснение;
- ссылка «реплика N»: если на неё нажать, переписка прокрутится к нужному сообщению и подсветит его. У звонков
  ещё и плеер перемотается на этот момент.

Если модель не уверена в ответе (уверенность ниже 75%), критерий помечается как «Проверить».

### Пример сценария

1. **Подать апелляцию.** Откройте любой диалог, найдите в карточке блок «Подать апелляцию», выберите критерий и
   напишите, с чем не согласны.
2. **Рассмотреть апелляцию.** Переключите роль на «Проверяющий», откройте раздел «Апелляции» и нажмите
   «Подтвердить» или «Изменить», указав причину. В карточке будет видно исходную оценку, решение и новый итог.
3. **Добавить свой критерий.** В разделе «Чек-листы» добавьте критерий, например «Оператор чихнул в чат»
   (тип Да/Нет, штрафной), и сохраните. Потом в карточке диалога выберите новую версию чек-листа и нажмите
   «Оценить заново». Модель понимает критерий по его описанию, код трогать не надо.
4. **Дообучить модель.** Если на новом критерии модель часто ошибается, рассмотрите по нему апелляции хотя бы
   в 5 разных диалогах. Затем в разделе «Апелляции» нажмите «Дообучить модель по решениям». Это займёт
   несколько секунд, перезапускать ничего не нужно.

## Команды для консоли

Все команды запускаются из папки проекта. Для оценки должен быть запущен сервис модели.
```
npm run eval -- --group DEV                    оценить весь набор DEV
npm run eval -- --group DEV --limit 5          только первые 5 диалогов
npm run eval -- --ids p1-ru-001,p1-kz-003      конкретные диалоги
npm run accuracy -- --gt data/gt-holdout       сравнить оценки модели с ручной разметкой
npm test                                       автотесты (сервис модели для них не нужен)
```

### Как загрузить новый набор диалогов

1. Откройте файл `.env` и впишите в строку `CQA_API_URL=` ссылку на API организаторов, но без `&group_id=...`
   на конце.
2. Перезапустите приложение (закройте окна и снова запустите `start.cmd`).
3. В разделе «Диалоги» введите в поле `group_id` код набора, нажмите «Загрузить», а потом «Оценить все».

Скачанный набор сохраняется в `data/<group_id>.json`, второй раз он уже грузится с диска. Можно обойтись и без
API: положить файл с диалогами в папку `data` и загрузить его по имени файла.

### Результаты контрольного набора

Контрольные чаты FBroker уже скачаны (`data/FBroker.json`) и оценены, результат лежит в
`results/prod/results.json`. Чтобы пересобрать его заново:
```
npm run eval -- --group FBroker --checklist default
npm run export -- --group FBroker --checklist default --out results/prod/results.json
```
В файле для каждого диалога есть итоговый балл, флаг грубой ошибки и баллы по секциям. Для каждого критерия —
ответ, баллы, вес, объяснение, реплики-доказательства (с текстом и временем), проверенный участок, причина N/A
и уверенность модели. Дополнительный набор Swap тоже скачан (`data/Swap.json`), но пока не оценивается.

## Насколько хорошо работает модель

Мы проверили модель на 13 реальных диалогах, которые она не видела во время обучения (это 104 ответа по
критериям), и сравнили с двумя простыми способами:

| | Всегда самый частый ответ | Правила на регулярках | **Наша модель** |
|---|---|---|---|
| Совпадение с ручной разметкой | 76.0% | 74.0% | **82.7%** |
| macro-F1 по критериям | 42.3 | 52.4 | **71.1** |

Что получилось хорошо: модель находит все грубые ошибки (проверяли на синтетике и на реальных диалогах, куда
специально добавили нарушения), а одна оценка занимает около 0.1 секунды.

Что получилось хуже:
- критерии «корректность консультации» и «управление диалогом» — модель ничего не знает о продуктах брокера,
  поэтому ей сложно понять, правильно ли ответил оператор;
- новые критерии, которых не было при обучении, модель часто уверенно оценивает как «нет». Тут помогает
  дообучение на апелляциях;
- ручная разметка, с которой мы сравниваем, черновая и тоже может содержать ошибки, а 13 диалогов — это мало.

Подробный отчёт с цифрами: [local-model/REPORT.md](local-model/REPORT.md).

## Обучение модели заново (не обязательно)

Готовые веса уже лежат в `local-model/weights/cqa-local-v1.pt` (около 20 МБ), так что для работы ничего обучать
не надо. Если хотите повторить обучение:
```
npm run datagen
local-model\.venv\Scripts\python.exe local-model\train.py
local-model\.venv\Scripts\python.exe local-model\predict.py
local-model\.venv\Scripts\python.exe local-model\evaluate.py --models majority,rules,cqa-local-v1 --detail gt-holdout
```
- `npm run datagen` генерирует обучающие данные, около минуты. Ему нужен Python, который запускается как `py -3`.
- `train.py` обучает модель, около 40–50 минут на обычном процессоре. Новые веса сохранятся поверх старых.
- `predict.py` и `evaluate.py` считают метрики на тестовых наборах.

Как устроена модель, написано в [local-model/README.md](local-model/README.md), а как генерируются данные — в
[local-model/datagen/README.md](local-model/datagen/README.md).

## Частые проблемы

- **При оценке ошибка «Модель не запущена».** Не работает окно «CQA model». Запустите `start.cmd` ещё раз или
  запустите сервис модели вручную (команда выше). Если окно сразу закрывается, проверьте, что `setup.cmd` прошёл
  без ошибок.
- **`setup.cmd` пишет, что нет Node.js или Python.** Установите их (ссылки в начале) и запустите `setup.cmd`
  заново. Если Python установлен, но не находится, скорее всего не стояла галочка «Add python.exe to PATH».
- **Порт 3000 или 8000 уже занят.** В файле `.env` поменяйте `PORT=3001` для приложения, а для модели задайте
  `LOCAL_MODEL_PORT=8001` и `LOCAL_MODEL_URL=http://127.0.0.1:8001`.
- **Не проигрывается запись звонка.** Ссылка на запись живёт примерно час. Обновите страницу или нажмите
  «Открыть плеер».
- **Хочется начать с чистого листа.** Закройте приложение и удалите папку `storage` — в ней хранятся все оценки,
  апелляции и версии чек-листов.

## Структура проекта

```
setup.cmd, start.cmd       установка и запуск под Windows
server/                    сервер на Node.js + Express
  index.js                 REST API
  model/                   обращение к сервису модели и сборка результата оценки
  scoring.js               подсчёт итогового балла
  analytics.js, business.js  сводка, операторы, тревоги
  store.js                 хранение данных в JSON-файлах (папка storage/)
  seed/checklist.default.json  стартовый чек-лист на 8 критериев
web/                       интерфейс: обычные HTML, CSS и JavaScript
local-model/               нейросеть: обучение, сервис, веса, генератор данных, отчёт
data/                      наборы диалогов и ручная разметка
results/prod/              результаты по контрольному набору
docs/                      задание и исходный чек-лист (PDF)
scripts/                   консольные команды
```

Как считается итог: берём все применимые критерии, для каждого умножаем вес на долю набранных баллов, складываем
и делим на сумму весов, потом умножаем на 100. Критерии с ответом N/A в расчёт не идут, их вес просто
перераспределяется между остальными. Грубая ошибка на балл не влияет — она показывается отдельным флагом.
